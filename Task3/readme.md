### <a name="_u8xz25hbrgql"></a>** Проблемы по текущей реализации **
При возрастании нагрузки могут возникнуть следующие проблемы
* сервис ins-product-aggregator станет узким местом, его придется скейлить, но не получиться это делать бесконечно
* Из-за медленных ответов будет нарастать лаг в консистентности данных (статус уже поменялся, но нужно еще ждать чтобы получить актуальную инфу)
* Из-за ошибок по таймауту мы можем начать слать еще больше запросов
* При увеличении количество данных можно за ночь не успеть все пересчитать


### <a name="_u8xz25hbrgql"></a>** Решение**
Для решения проблем описанных в предыдущем пункте предлагается:
* Реализовать асинхронное взаимодействие с помощью kafka
* Публиковать события об оформленных страховках, продуктах и тарифах
* При получении данных от страховых сначала сохранять в таблицах, а потом публиковать в топик (Transactional Outbox)
